# УСТАНОВКА LeadParser С НУЛЯ — инструкция для Claude Code

> **Привет, Claude Code!** Этот файл тебе скинул пользователь, чтобы ты помог ему
> установить себе **LeadParser** — личный парсер заявок из Telegram. Пользователь
> может быть НЕ программистом. Твоя задача — провести его по шагам ниже,
> по одному шагу за раз, дожидаясь подтверждения, помогая с командами и не убегая
> вперёд. Разговаривай просто, по-человечески, без занудства.
>
> **Как вести себя:**
> - Иди строго по шагам 0 → 9. Не прыгай.
> - После каждого шага спрашивай: «сделал? что получилось?» и жди ответа.
> - Команды в терминале выполняй сам через свой Bash-инструмент, где можешь.
> - То, что человек должен сделать руками в браузере/телефоне (создать аккаунт,
>   нажать кнопку на сайте) — объясняй словами и жди, пока сделает.
> - Секреты (`API_HASH`, `STRING_SESSION`, токены) — НИКОГДА не проси вставлять
>   в код или в чат лишний раз. Они идут только в GitHub Secrets.

## Что это такое (объясни человеку своими словами)

Парсер читает сообщения в Telegram-чатах, где ты состоишь, отбирает по ключевым
словам реальные заявки (например «ищу спеца по продажам / маркетингу / ИИ») и
складывает их карточками в твой личный приватный канал. Ты просто читаешь ленту
заявок вместо того, чтобы вручную мониторить десятки чатов.

- **Бесплатно** — крутится на GitHub Actions по расписанию (каждые ~10 минут).
- **Безопасно** — аккаунт только читает, ничего не пишет, сам в чаты не вступает.
- **Без ИИ** — фильтрация по спискам слов, которые легко править.

**Нужно от человека заранее (предупреди его):**
1. Аккаунт на **GitHub** (бесплатный) — https://github.com
2. **Два аккаунта Telegram**:
   - **Парсер** — желательно «старый отлежавшийся» аккаунт, который состоит/вступит
     в нужные чаты. Он будет читать.
   - **Получатель** — основной аккаунт, которым человек читает заявки.
   - *(Можно начать и с одного аккаунта — тогда он и читает чаты, и читает канал.)*
3. Телефон с Telegram под рукой (для входа).
4. ~30–40 минут времени.

## ШАГ 0. Поставить инструменты на комп

Нужны **Python 3** и **git**. Проверь, что стоят:

```bash
python3 --version
git --version
```

- Если Python нет — поставить с https://python.org (или `brew install python` на Mac).
- Если git нет — https://git-scm.com (или `brew install git` на Mac).

Когда обе команды показывают версию — шаг готов.

## ШАГ 1. Скачать код парсера

Код лежит в публичном репозитории. Склонируй его в удобную папку:

```bash
cd ~/Desktop
git clone https://github.com/echernigin-netizen/leadparser.git LeadParser
cd LeadParser
```

> Если репозиторий недоступен или человек получил код иначе (архивом от друга) —
> просто распакуй папку `LeadParser` на рабочий стол и `cd` в неё.

Проверь, что внутри есть файлы: `main.py`, `login.py`, `keywords.json`,
`requirements.txt`, `.github/workflows/run.yml`.

```bash
ls -la
```

**Важно:** это будет ЛИЧНАЯ копия. Дальше человек создаст СВОЙ репозиторий и СВОИ
секреты — ничего общего с чужим аккаунтом не останется.

## ШАГ 2. Установить зависимости и сбросить состояние

```bash
pip3 install -r requirements.txt
```

Сбрось файл состояния в чистый — чтобы не тянуть чужие «водяные знаки»:

```bash
echo '{ "watermarks": {}, "seen": [] }' > state.json
```

Очисти `chats.txt`, оставив только комментарии (по умолчанию парсер будет читать
ВСЕ группы, где состоит аккаунт — это удобно). Можно не трогать, если файл уже
пустой (без активных строк).

## ШАГ 3. Получить API_ID и API_HASH

Это ключи приложения Telegram (нужны Telethon для чтения через MTProto).

Объясни человеку — сделать руками:
1. Зайти на https://my.telegram.org под **аккаунтом-ПАРСЕРОМ** (тот, что будет читать чаты).
2. Войти по номеру телефона + код из Telegram.
3. Открыть **API development tools**.
4. Создать приложение (App title и short name — любые, например `leadparser`).
5. Скопировать два значения: **App api_id** (число) и **App api_hash** (длинная строка).

Пусть сохранит их во временный блокнот — понадобятся в шаге 4 и 7.

> ⚠️ Если Telegram не даёт войти на my.telegram.org из его страны/сети — нужен VPN.

---

## ШАГ 4. Сгенерировать STRING_SESSION (вход аккаунта-парсера)

`STRING_SESSION` — это «пропуск», который позволяет парсеру заходить в Telegram
на серверах GitHub без повторного ввода кода.

Запусти локально скрипт `login.py` — он спросит данные и напечатает строку сессии:

```bash
python3 login.py
```

Скрипт попросит по очереди:
- `API_ID` — вставь число из шага 3,
- `API_HASH` — вставь строку из шага 3,
- номер телефона аккаунта-парсера (в формате `+7...`),
- код, который придёт в Telegram,
- пароль двухфакторки — если он включён.

В конце скрипт напечатает строку `STRING_SESSION` (очень длинная). 

> ⚠️ Эта строка = полный доступ к аккаунту. В чат её НЕ вставляй, в код НЕ коммить.
> Пусть человек скопирует её во временный блокнот — она пойдёт прямо в GitHub Secrets
> на шаге 7. Если строка случайно утекла — отозвать: Telegram → Настройки → Устройства.

> Если вход с компа не проходит (Telegram режет MTProto в некоторых сетях) — то же
> самое можно сделать в Google Cloud Shell https://shell.cloud.google.com или под VPN.

---

## ШАГ 5. Создать приватный канал «Заявки» (куда падают находки)

Объясни человеку — сделать в Telegram руками:
1. Создать **новый приватный канал**, назвать например «Заявки».
2. Сделать **аккаунт-парсер** владельцем или админом этого канала с правом постинга.
   (Если канал создавал сам парсер — он уже владелец, ок.)
3. Подписать **аккаунт-получатель** на этот канал (чтобы читать ленту).
4. Узнать **id канала**: переслать любое сообщение из канала боту @username_to_id_bot
   (или @getidsbot) — он покажет id вида `-100XXXXXXXXXX`. Сохрани этот id.

> Альтернатива каналу — доставка через бота (`DELIVERY_MODE=bot`). Канал проще,
> рекомендуй его. Бот-режим описан в README, если человек захочет.

## ШАГ 6. Создать свой репозиторий на GitHub и залить код

1. Человек заходит на https://github.com → **New repository**.
   - Имя: например `leadparser`.
   - Тип: **Public** (публичный — чтобы минуты GitHub Actions были бесплатны и
     безлимитны; секреты при этом НЕ светятся, они хранятся отдельно).
   - Без README/gitignore (они уже есть в коде).
2. Привяжи локальную папку к новому репозиторию и запушь. Подставь его ник и имя репо:

```bash
git remote remove origin 2>/dev/null
git remote add origin https://github.com/ЕГО_НИК/leadparser.git
git add -A
git commit -m "init: my leadparser"
git branch -M main
git push -u origin main
```

> GitHub попросит залогиниться. Проще всего — через **GitHub CLI** (`gh auth login`)
> или Personal Access Token вместо пароля. Помоги с этим, если затык.

---

## ШАГ 7. Прописать секреты в GitHub

На GitHub: репозиторий → **Settings** → **Secrets and variables** → **Actions** →
**New repository secret**. Добавь по одному (имя = значение):

| Имя секрета | Значение |
|---|---|
| `API_ID` | число из шага 3 |
| `API_HASH` | строка из шага 3 |
| `STRING_SESSION` | длинная строка из шага 4 |
| `DELIVERY_MODE` | `channel` |
| `TARGET_CHAT` | id канала из шага 5 (вида `-100...`) |

> Это всё. `BOT_TOKEN` и `RECEIVER_CHAT_ID` нужны только для бот-режима — в режиме
> `channel` их пропускаем.

---

## ШАГ 8. Включить и запустить

1. На GitHub: вкладка **Actions** → если попросит подтвердить включение workflow —
   нажми «I understand my workflows, enable them».
2. Слева выбери workflow **lead-parser** → кнопка **Run workflow** → **Run workflow**.
   (Именно «Run workflow», НЕ «Re-run».)
3. Через минуту-две открой прогон → шаг **Run parser** → смотри лог.
   - Строка `авто-режим: найдено групп N` — значит парсер видит чаты.
   - Если `найдено групп 0` — аккаунт-парсер пока ни в одной группе. См. шаг 9.
4. Дальше парсер сам крутится по расписанию (~каждые 10 мин, GitHub может задерживать).

---

## ШАГ 9. Наполнить и докрутить (ежедневка)

1. **Вступай аккаунтом-парсером в целевые чаты** — вручную, по **5–10 в день**
   (резкие массовые вступления ловит антиспам). Скрипт сам НЕ вступает.
   Как вступил — чат автоматически попадает в обработку.
2. Заявки начнут падать карточками в канал «Заявки». Читай получателем.
3. **Докручивай фильтр** под себя — файл `keywords.json` (правится прямо на GitHub:
   открыть файл → ✏️ → Commit changes, перезапуск не нужен):
   - три списка: `intent` (триггеры намерения), `niches` (термины ниш),
     `negative` (минус-слова);
   - заявка проходит, если есть хоть один `intent` И хоть один `niches` И НЕТ ни
     одного `negative`;
   - **лезет мусор** → добавь слово в `negative`;
   - **пропускает нужное** → добавь термин в `niches` или триггер в `intent`.

## ⚠️ Чего НЕЛЬЗЯ (предупреди человека)

- ❌ Не жать **«Re-run all jobs»** — гоняет старый прогон и может слать повторы.
  Только **Run workflow** или ждать расписание.
- ❌ Не сбрасывать `state.json` без причины — это «водяные знаки», без них пойдут
  повторы старых сообщений.
- ❌ `STRING_SESSION` — только в Secrets. Не в код, не в чат. Утекла → отозвать
  сессию в Telegram (Настройки → Устройства).

## Если что-то сломалось (траблшутинг)

| Симптом | Что делать |
|---|---|
| `найдено групп 0` | Аккаунт-парсер ни в одной группе — вступить в целевые чаты |
| `STRING_SESSION недействителен` | Перевыпустить сессию: снова `python3 login.py` → обновить секрет |
| Красный крест на прогоне | Открыть лог шага **Run parser**, прислать последние строки сюда |
| Приходят повторы | Не жать «Re-run»; проверить, что шаг «Commit updated state» коммитит `state.json` |
| Мусор в канале | Добавить слова в `negative` в `keywords.json` |
| Telegram не пускает на вход | Включить VPN или генерить сессию в Google Cloud Shell |
