# LeadParser — личный парсер заявок из Telegram

Читает поток сообщений из заданных Telegram-чатов, отбирает по ключевым словам
реальные заявки в нишах **продажи / маркетинг / ИИ-автоматизация** и присылает
находки в твой отдельный аккаунт. Личный аналог LeadRadar: бесплатно,
read-only, без авторассылок.

- **Бесплатно** — крутится на GitHub Actions по расписанию (cron каждые ~10 мин).
- **Безопасно** — аккаунт-парсер только читает, ничего не пишет в чаты и в личку, сам в чаты не вступает.
- **Просто править** — списки слов в `keywords.json`, список чатов в `chats.txt`, код трогать не надо.

---

## Как это работает

Два логических участника (какой реальный аккаунт играет какую роль — решаешь ты при настройке):

- **Парсер (userbot)** — аккаунт, который уже состоит в нужных чатах и читает их через MTProto (Telethon). Только чтение.
- **Получатель** — куда падают отобранные заявки. Читаешь вторым аккаунтом.

Рекомендация по умолчанию: **парсер = старый «отлежавшийся» аккаунт** (устойчивее к антиспаму как читатель), получатель — другой твой аккаунт.

Модель работы — **поллинг**: каждый запуск Actions забирает сообщения, появившиеся
с прошлого раза, фильтрует, доставляет карточки, обновляет «водяной знак» в `state.json`.

### Логика отбора (без LLM, чисто ключевые слова)

Сообщение считается заявкой, если выполнены ВСЕ три условия:
1. есть ≥1 **триггера намерения** (ищу, нужен, посоветуйте…), И
2. есть ≥1 **термина ниши** (продажи / маркетинг / ИИ), И
3. НЕТ ни одного **минус-слова** (продам, курс, вакансия…).

Плюс: игнор сообщений короче ~15 символов и собственных сообщений парсера.
К каждой заявке проставляется тег ниши (`🟢 Продажи` / `🔵 Маркетинг` / `🟣 ИИ`).

> Списки в `keywords.json` — отправная точка. Докручивай под себя: это самый
> влияющий на качество параметр.

## Способы доставки

Параметр `DELIVERY_MODE`:

- `channel` (по умолчанию) — парсер постит заявки в **приватный канал**, где он админ. Получатель подписан и читает единой лентой.
- `bot` — парсер передаёт находки боту (@BotFather), бот пушит их в чат получателя (получатель один раз жмёт `/start` у бота).

Логика парсинга от режима не зависит — переключается конфигом.

## Разовая настройка

### 1. Создай публичный репозиторий на GitHub
Публичный — чтобы минуты Actions были бесплатны и безлимитны.
Секреты при этом не светятся: они хранятся в GitHub Secrets, в код не попадают.
Залей в него содержимое этой папки.

### 2. Получи API_ID и API_HASH
На <https://my.telegram.org> → API development tools.

### 3. Сгенерируй STRING_SESSION (под аккаунтом-парсером)
Локально или в Replit:
```bash
pip install Telethon
python login.py
```
Введёшь номер парсера, код из Telegram, при необходимости 2FA-пароль.
Скрипт напечатает строку `STRING_SESSION` — скопируй её.

> ⚠️ `STRING_SESSION` = полный доступ к аккаунту. В репозиторий НЕ коммить,
> только в Secrets. Если утекла — отзови сессию: Telegram → Настройки → Устройства.

### 4. Настрой доставку

**Режим `channel`:**
- Создай приватный канал.
- Добавь аккаунт-парсер админом с правом постинга.
- Узнай id канала (например, переслав сообщение боту `@username_to_id_bot`, формат `-100...`).
- В секреты: `DELIVERY_MODE=channel`, `TARGET_CHAT=-100...`.

**Режим `bot`:**
- Создай бота через @BotFather, возьми токен.
- Получатель один раз жмёт `/start` у бота.
- Узнай chat_id получателя (например, через `@userinfobot`).
- В секреты: `DELIVERY_MODE=bot`, `BOT_TOKEN=...`, `RECEIVER_CHAT_ID=...`.

### 5. Пропиши секреты
GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Secret | Когда нужен | Что это |
|---|---|---|
| `API_ID` | всегда | с my.telegram.org |
| `API_HASH` | всегда | с my.telegram.org |
| `STRING_SESSION` | всегда | строка сессии парсера (из `login.py`) |
| `DELIVERY_MODE` | всегда | `channel` или `bot` |
| `TARGET_CHAT` | режим `channel` | id приватного канала |
| `BOT_TOKEN` | режим `bot` | токен бота от @BotFather |
| `RECEIVER_CHAT_ID` | режим `bot` | chat_id получателя |
| `AUTO_DISCOVER` | опционально | `1` — читать ВСЕ группы парсера автоматически (см. ниже) |

### Авто-режим источников (`AUTO_DISCOVER`)

Авто-режим включается, если **`chats.txt` пуст** (по умолчанию) или явно задан
секрет `AUTO_DISCOVER=1`. В этом режиме парсер на каждом прогоне сам читает все
группы/супергруппы, в которых состоит аккаунт. Вступил в новый чат вручную — он
автоматически попадёт в обработку, файл править не надо. Канал доставки при этом
не читается, broadcast-каналы пропускаются (заявки ищем в группах).

Если в `chats.txt` перечислены чаты — читаются только они (ручной режим).

### 6. Заполни chats.txt
По одному чату на строку: `@username`, ссылка или числовой id.
Только те чаты, **в которых парсер уже состоит**.
Строки с `#` и пустые — игнорируются.

### 7. Включи Actions
Вкладка **Actions** → разрешить workflow. Дальше крутится сам по cron.
Можно дёрнуть вручную: Actions → `lead-parser` → **Run workflow**.

## Эксплуатация и безопасность

- Вступай в чаты **вручную и постепенно** (5–10 в день) — скрипт сам не вступает.
- Парсер только читает: не пишет в чаты, не шлёт в личку.
- `FloodWaitError` обрабатывается (подождать/пропустить, не падать).
- Ошибка одного чата не роняет весь прогон — он логируется и пропускается.
- Состояние (`state.json`) воркфлоу коммитит обратно в репозиторий, дублей между прогонами нет.

## Структура

```
.
├── main.py                    # точка входа: чтение → фильтр → доставка → state
├── login.py                   # разовый помощник: печать STRING_SESSION
├── keywords.json              # списки слов (намерение / ниши / минус-слова)
├── chats.txt                  # список чатов-источников
├── state.json                 # авто-управляемое состояние (последние id)
├── requirements.txt
├── .gitignore
└── .github/workflows/run.yml  # cron каждые ~10 минут
```
